# Qwen3-1.7B 购物执行器 V2

本实验在本机训练购物执行子任务：工具选择、约束参数、必要追问、结果编号选择和失败恢复。
不替换默认主模型，也不将固定规则渲染的成功算成模型原始能力。

本轮已完成，训练耗时 116.72 分钟，峰值 CUDA 分配 4.47 GiB。
严格单步测试 94/300 → 248/300，业务校验后完整任务 16/40 → 28/40；
数据均为合成受控场景，仍有多轮恢复和工具协议问题。
详细结果和失败分析见 [最终报告](../docs/executor_sft_v2_report.md)。

## 数据

`eval/executor_v2/`：1,500 train、200 dev、300 test、40 个完整 Agent 任务。
冻结后禁止覆盖；`build_dataset_v2.py` 遇到已有目录会拒绝执行。
训练集分配：400 正常调用、350 追问/冲突、300 结果选择、250 失败恢复、200 多步保持。
共 30 个业务家族，存在模板重复。类别实体和主要表达跨 split 隔离，但这不是生产用户分布，
也不代表 2,000 种独立决策模式。训练/开发的准确目标只监督最后一个 assistant 消息。

商品结果目标采用 `{"item_ids":["实际编号"]}`。模型选择商品，应用依据真实工具结果渲染
SKU、单件标价、购买数量和估算到手总价；模型不提供自行生成的价格事实。
非空结果的原始评分检查 JSON Schema、编号集合、顺序、去重和数量，其他文本仍含关键词规则，
因此通过不等于完整语义正确。空结果只能说明当前检索范围，不能宣称全站无货。
单步评分只接受标注的下一步动作；先查询品类知识等允许的准备动作也可能被判为不匹配，
所以不能将全部未通过都视为业务错误。完整任务另测实际执行效果，工具空间仅包含商品查询和
目录解析，与单步测试的三个工具不同；每种测试内部的基座和 adapter 使用相同工具空间。

## 训练与复现

独立环境 `training/.venv`，可选依赖见 `requirements-qlora.txt`。
固定基座 `data/models/Qwen3-1.7B`，revision
`70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`。
Windows/Blackwell 量化依赖依据 [bitsandbytes 官方安装文档](https://huggingface.co/docs/bitsandbytes/v0.50.2/en/installation)。

```powershell
training/.venv/Scripts/python.exe -u -m training.train_sft --model data/models/Qwen3-1.7B --train eval/executor_v2/train.jsonl --dev eval/executor_v2/dev.jsonl --output training/outputs/NEW-RUN --epochs 2 --rank 8 --max-length 3072 --qlora --trim-cuda-cache
```

NF4 双重量化，BF16 计算，q/k/v/o LoRA，r=8、alpha=16、dropout=0.05，
学习率 1e-4，梯度累积 8，seed=42。启用梯度检查点，只训练 3,211,264 个参数。
释放闲置 CUDA 缓存用于缓解长短样本交替时 Windows 显存缓存压力。
权重只根据每轮开发集 loss 选择；禁止使用 test 选择 epoch 或改评分规则。
`config.json`、`progress.jsonl`、`metrics.json` 保存参数、数据哈希、进度和选择证据。

## 对照评测

```powershell
training/.venv/Scripts/python.exe -m training.evaluate_executor_v2 --model data/models/Qwen3-1.7B --output eval/reports/executor-v2/NEW-BASE
training/.venv/Scripts/python.exe -m training.evaluate_executor_v2 --model data/models/Qwen3-1.7B --adapter training/outputs/NEW-RUN/adapter --output eval/reports/executor-v2/NEW-ADAPTER
```

两者统一以 BF16 基座推理，不启用采样、模型回退或响应缓存，最多生成 256 tokens。
本次 adapter 通过 PEFT 非合并加载，LoRA 张量为 FP32；没有评测合并权重的最优推理速度。
QLoRA 是训练时的内存配置，评测 adapter 会加载到 BF16 基座，不能混淆两种精度。
每次使用新输出目录，原始响应、解析错误、截断、时延与逐案例评分全部保存。

完整任务使用 `evaluate_agent_v2.py`，需要先启动 `serve_executor.py` 的本地服务，
端口 8010，上下文窗口 8192。派发器、词法目录和运税均为明确的合成夹具；
执行模型、MainAgent/fork、真实工具、领域过滤、跨轮状态和业务校验实际运行。
验收检查最终商品编号、SKU、标价、购买数量、估算到手价、预算更新及币种追问。
不衡量主规划模型智能，也不代表真实检索质量或实际结账准确率。

本次顺序驱动为 `run_comparison_v2.py`，固定本次正式训练目录；仅等待已验证的训练 PID，
然后依次运行基座/adapter 各 300 条冻结决策、各 40 个完整任务，结束后停止自己创建的服务。
已有端口占用时拒绝接管。状态与原始日志在 `eval/reports/executor-v2/`。

## 手动启用本次模型

评测结束后会停止临时服务。如需体验本次 adapter，单独启动：

```powershell
training/.venv/Scripts/python.exe -m training.serve_executor --model data/models/Qwen3-1.7B --adapter training/outputs/executor-v2-1.7b-qlora/adapter --name globex-v2-1.7b-adapter --context-window 8192
```

在另一个 PowerShell 窗口为应用进程设置以下变量，再按主 README 启动后端：

```powershell
$env:EXECUTOR_MODEL_NAME = "globex-v2-1.7b-adapter"
$env:EXECUTOR_BASE_URL = "http://127.0.0.1:8010/v1"
$env:EXECUTOR_API_KEY = "local-no-key"
$env:EXECUTOR_CONTEXT_WINDOW = "8192"
```

这里只是操作示例，本次执行没有替你修改 `.env` 或默认路由。关闭该窗口可清除其中设置的
进程环境变量；具体回退配置与持久化配置的回滚见原 `training/README.md`。

## 已实现的业务边界和限制

- 显式预算、币种、配送、购买数量、候选数量、预算口径、品牌和目录品类进入约束状态。
  子任务继承来源明确的父状态，不能用规划器改写的任务描述覆盖已确认条件。
- 商品过滤区分单件、商品小计、估算到手预算，检查主 SKU 库存，复用同一次报价，按商品 ID 去重。
- 品类只接受标准名称或目录中配置的唯一别名；模糊/多义候选必须确认。
- 跨会话偏好投影到工作记忆；可识别的品牌排除进入硬约束，显式撤回才清除，冲突先确认。
- 当前解析器是保守的中英文显式表达规则，不能覆盖所有自然语言、任意品牌、所有国家或复杂否定。
  未覆盖表达仍依赖模型理解与追问，不可宣称通用 NLU 硬保证。原有无品类元数据的索引保持兼容，
  无法自动解析别名；生产 Faiss 索引已提供目录元数据。
- 商品输出校验保留原始模型结果与改写记录。父 Agent 汇总能透传本轮带有校验凭据的子任务商品回答，
  避免再次改写价格；凭据有容量限制且不跨进程持久化，混合未校验子任务仍需进一步完善。
- 本次不改变默认模型配置。启用本地 executor 仍使用现有显式模型路由配置，需独立版本名，
  不能把新 adapter 覆盖到旧模型版本名下。
