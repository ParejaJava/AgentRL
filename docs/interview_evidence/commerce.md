# COMMERCE-001：个性化、到手价与订单边界

偏好 Store 跨会话保存 like/dislike/黑名单；每轮只投影相关且有上限的偏好到工作记忆，同时商品 User Tower 把偏好转成向量参与检索。黑名单是确定性排除规则，不交给模型自行遵守。

只有请求提供 `ship_to` 才计算到手价。Money 使用整数最小货币单位和 Decimal 规则；计价端口组合汇率、数量、运费、关税、免税阈值及规则版本。非法币种、数量、SKU、目的地和 `top_k` 在工具 schema、应用命令或领域对象边界被拒绝。

订单能力只创建、查询和取消“订单意向”。创建前要求本轮存在商品搜索证据和用户明确确认，仓储使用幂等键避免重复请求生成重复意向。

正式专项报告在固定 Commit 上执行偏好、计价、订单和商品工具共 29 项测试，**29/29 通过**。这证明规则和失败无副作用，不代表真实海关价格、库存或支付链路已接通。证据见 [commerce-001.json](results/20260909T073736Z-offline/commerce-001.json)。

## STAR 话术

- S：个性化容易退化为 Prompt 文本，到手价容易出现浮点误差，Agent 还可能越过确认直接写订单。
- T：让偏好真正影响召回，并把交易写操作约束在可审计边界内。
- A：偏好双写到工作记忆/User Tower；Money/Decimal 值对象；`ship_to` 条件计价；搜索证据 + 用户确认 + 幂等键三道门。
- R：专项测试报告证明规则和无副作用失败；项目不宣称真实付款、库存占用、退款或下单成功。
